# Corrections for bio.tools

Generated by `pipeline/export_biotools.py` from
<https://github.com/thirtysix/awesome-regulatory-genomics>, a catalog built on
bio.tools. Found by cross-checking each record's description against its own
paper. One file per category, because the evidence behind them differs and you
may well want to take one and not another.

**Every record in the two upload files was POSTed to**
`https://bio.tools/api/tool/validate/` **and accepted** before being written here,
so nothing should fail on ingest. The only complaint suppressed is the
create-validator's "this ID already exists", which an update does not have to
answer.

Each record carries a `_correction` field saying what changed. Strip it before
upload if it is not wanted; it is not part of biotoolsSchema.

### publications.json

The class NOBAI belonged to (issue #737). A transposed digit or a wrong paper
resolves cleanly, so nothing that checks whether a reference resolves can see
it. Found by comparing each tool's description with its paper's abstract and
noticing they were about different subjects. Two were preprints whose published
version exists; both were confirmed by title before swapping.

### edam-operations.json

Each record had one operation that its own topics, inputs, outputs and
description all contradict: a cytochrome-P450 inhibition predictor annotated
`Promoter prediction`, a protein beta-strand predictor on the same term. Only
that one operation is removed; everything else is untouched.

31 more were held back rather than sent:

- **15** would have been left with no operation at all. A record with a wrong
  operation is better than one with none, so those need a replacement term
  rather than a deletion, and that is your judgement rather than ours.
- **16** carry a term your validator rejects, so they cannot be
  updated by anyone until the term migration reaches them. An unmodified
  GET-then-PUT of these returns 400. The pairs we hit:

  | term served | URI |
  | --- | --- |
  | `Editing` | `http://edamontology.org/operation_3096` |
  | `Data submission, annotation and curation` | `http://edamontology.org/topic_0219` |
  | `Protein-protein interaction prediction` | `http://edamontology.org/operation_2464` |
  | `Deposition` | `http://edamontology.org/operation_3431` |

### homepages.json

A report rather than records, for two reasons: `homepage_status` is
server-managed, and we found no verified replacement URL for any of them, so
there is nothing to apply. Per your note about transience, every URL here
returned 404 or 410 on **two checks nine days apart** (2026-07-28 and
2026-08-06), each with a retry. One entry that recovered between checks was
dropped.

Offered in case it is useful alongside OpenEBench; ignore it if not.

## Not included

**~43 records whose publication is a platform paper rather than the tool's own**,
mostly Bioconductor packages carrying `pmid:25633503`. We do not think these are
43 errors. For a package that has never had its own paper, pointing at the
platform may be exactly what the maintainer intends. "The paper you should cite"
and "the paper that describes this software" are different things and the schema
has one field for both. That is a design question rather than a correction, so
there is no file for it.

## If something here is wrong

Please say so and we will fix the derivation rather than patch the output. The
same process produced findings we have since had to correct ourselves, so a
sceptical read is welcome.
